# 冷区曝光路径消融：召回层注入 vs 排序层加分

> 实验时间：2026-10-13　协议：20000 用户 / leave-last-5-out / seed=42 / 同候选池同协议
> 命令：`EVAL_V6_MB=null EVAL_USE_CKPT=1 EVAL_COLD_INJECT=<n> EVAL_COLD_BOOST=<b> python scripts/run_eval_v6.py`
> 目的：隔离「召回层冷区注入」与「排序层冷区加分」对冷区命中率的**各自**贡献。

---

## 1. 为什么要做这个实验

稿件原先把"冷区定向注入"当作核心机制。但注入与加分在现有实现里**同时开启**，
二者贡献从未分离；而 2026 年的主流工作（排序层去偏路线，如 Abdollahpouri et al.
2020、Zhao et al. 2024 综述所示）都在**排序层**做去偏，若我们的增益其实也来自
排序层，那么"召回层注入"这个差异化主张就不成立。因此做 2×2 消融，让数据说话。

> 经 arXiv / Semantic Scholar / Crossref 多轮检索**未能核实**（无对应论文命中），

## 3. 结论

### （1）冷区命中率 100% 由排序层加分决定，与召回层注入无关

加分 0.20 → ColdHit 0.0055；加分 0 → ColdHit 0.0000。
在**加分固定为 0.20** 时，注入从 12 关到 0，ColdHit **纹丝不动**（0.0055 → 0.0055）。

⇒ 冷区商品通过「用户历史品类 → 该类目热门榜」这条既有路径就已经进了候选池，
**召回不是瓶颈**。注入的 204 万条商品没有一条转化为冷区命中。

### （2）召回层注入是无效组件，且轻微有害

| 对比（加分固定 0.20） | 注入 12 | 注入 0 | 差值 |
|---|---|---|---|
| 候选池均值 | 2711 | 2660 | −51/用户 |
| R@10 | 0.0137 | 0.0138 | **+0.0001** |
| N@10 | 0.0070 | 0.0071 | **+0.0001** |

关掉注入后召回与 NDCG **双双不降反升**——注入只是在稀释候选池。
同理在加分 0 时：注入 12 的 R@10/N@10 为 0.0140/0.0075，注入 0 为 0.0140/0.0076。

### （3）排序层加分的代价可以精确量化

加分 0 → 0.20：ColdHit 0.0000 → 0.0055，代价 R@10 0.0140 → 0.0137（**−2.1%**）、
N@10 0.0076 → 0.0070（**−7.9%**）。这是一个干净的、可辩护的权衡点。

## 4. 对作品定位的影响（必须据此修订）

1. **撤回**"我们在召回层做冷区注入，填补了排序层去偏路线的空白"这一主张。
   本项目在这条赛道上并不占空位——我们的机制同样在排序层。
2. 可辩护的说法改为：**我们量化了冷区曝光的两条路径，证明在本数据形态下
   瓶颈在排序而非召回，并给出加分的精确代价曲线与注入无效的证据。**
   这仍是一个有价值的结论（工程上直接省掉 204 万条无效注入），但从
   "机制创新"降格为"测量与归因"。
3. 建议的系统改动：删除冷区注入（`COLD_INJECT_PER_CAT=0`），
   预计 R@10 0.0137→0.0138、N@10 0.0070→0.0071，ColdHit 不变。
   **但这会改变 10-12 冻结的指标，需先拍板再动。**

本次是第二次：**一个被写进核心机制的组件，在干净消融下被证明没有贡献**。
